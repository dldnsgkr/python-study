# 20 · 파이썬다움 — 관용구와 안티패턴

`idioms · code review checklist`

## 바꿔 쓰기 표

| 대신 이렇게 | 이건 피하세요 |
| --- | --- |
| `for i, x in enumerate(xs)` | `for i in range(len(xs))` |
| `for a, b in zip(xs, ys)` | 인덱스로 두 리스트 동시 접근 |
| `if xs:` | `if len(xs) > 0:` |
| `if x is None:` | `if x == None:` |
| `d.get(k, default)` | `if k in d: d[k] else default` |
| `with open(...) as f:` | `f = open(...)` + `f.close()` |
| `"".join(parts)` | 루프 안 `s += part` |
| `isinstance(x, T)` | `type(x) == T` (상속을 놓친다) |
| `except Exception:` | `except:` |
| 기본값 `None` + 안에서 생성 | 가변 기본 인자 `[]`, `{}` |
| 제너레이터로 스트리밍 | 전체를 리스트로 읽고 순회 |
| `pathlib.Path` | 문자열 경로 `+ "/"` 조합 |

## The Zen of Python 실전 해석

- **명시가 암시보다 낫다** — 마법 같은 메타프로그래밍보다 지루하고 읽히는 코드가 낫습니다.
- **평평한 것이 중첩된 것보다 낫다** — 조기 반환(guard clause)으로 들여쓰기를 줄이세요.
- **특수한 경우가 규칙을 어길 만큼 특별하지 않다** — 그러나 실용성이 순수함을 이깁니다.
- **오류는 조용히 넘어가면 안 된다** — `except: pass`는 미래의 자신에게 보내는 시한폭탄입니다.

*중첩 줄이기*

```python
# 이전
def process(order):
    if order is not None:
        if order.is_valid:
            if order.items:
                return do_work(order)
    return None

# 이후 — 조기 반환
def process(order):
    if order is None:
        return None
    if not order.is_valid:
        return None
    if not order.items:
        return None
    return do_work(order)
```

## 코드 리뷰 체크리스트

- [ ] 가변 기본 인자를 쓰지 않았는가
- [ ] 클래스 속성에 가변 객체를 두지 않았는가
- [ ] 순회 중에 컨테이너를 수정하지 않는가
- [ ] 모든 `except`가 구체적인 타입을 잡고, 원인을 `from`으로 보존하는가
- [ ] `finally`에 `return`이 없는가
- [ ] 파일·소켓·락을 `with`로 관리하는가
- [ ] `open()`에 `encoding`을 명시했는가
- [ ] `datetime`이 aware이고 UTC로 저장되는가
- [ ] 금액 계산에 `float` 대신 `Decimal`/정수를 쓰는가
- [ ] 데코레이터에 `@functools.wraps`가 붙어 있는가
- [ ] 로깅이 f-string이 아니라 `%s` 인자 형태인가
- [ ] 공개 함수에 타입 힌트와 `__repr__`이 있는가
- [ ] 큰 데이터를 리스트로 전부 읽지 않고 스트리밍하는가
- [ ] 이벤트 루프 안에서 블로킹 호출을 하지 않는가
- [ ] 테스트가 시간·난수·네트워크에 의존하지 않는가
