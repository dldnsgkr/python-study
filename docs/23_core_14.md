# 14 · 모듈·패키지·임포트 시스템

`sys.modules · __main__ · 순환 import`

`import foo`가 하는 일: ① `sys.modules` 캐시 확인 → ② 없으면 `sys.path`에서 찾기 → ③ 모듈 객체를 만들고 **파일 전체를 위에서 아래로 실행** → ④ `sys.modules["foo"]`에 등록 → ⑤ 현재 네임스페이스에 이름 바인딩.

*import 형태*

```python
import package.module              # 전체 경로로 접근
from package import module         # 권장: 모듈 단위로 가져오기
from package.module import func    # 짧지만 출처가 흐려진다
from package.module import func as f
from . import sibling              # 상대 임포트 (패키지 내부에서만)
from .models import User

from module import *               # 금지 — 이름 충돌과 추적 불가
```

**💡 Tip**

실무 기본값은 `from package import module` 후 `module.func()`입니다. 호출부에서 함수의 출처가 보이고, 순환 임포트에도 훨씬 강합니다.

## 패키지 구조

*layout*

```text
myapp/
├── pyproject.toml
├── src/
│   └── myapp/
│       ├── __init__.py          # 패키지 표시 + 공개 API 정의
│       ├── __main__.py          # python -m myapp 로 실행되는 진입점
│       ├── config.py
│       ├── domain/
│       │   ├── __init__.py
│       │   └── order.py
│       └── adapters/
│           └── db.py
└── tests/
    └── test_order.py
```

`src/` 레이아웃을 쓰면 "설치된 패키지"를 테스트하게 되어, 현재 디렉터리 때문에 우연히 임포트가 되는 상황을 막습니다.

*__init__.py*

```python
# myapp/domain/__init__.py
from .order import Order, OrderLine
from .customer import Customer

__all__ = ["Order", "OrderLine", "Customer"]     # from ... import * 의 대상 + 공개 API 문서
```

## __name__ == "__main__"

*entry point*

```python
def main() -> int:
    ...
    return 0

if __name__ == "__main__":
    raise SystemExit(main())
```

모듈이 직접 실행되면 `__name__`은 `"__main__"`, 임포트되면 모듈 이름입니다. 이 가드가 없으면 임포트만 해도 프로그램이 실행되고, `multiprocessing`은 Windows/spawn 환경에서 **무한히 프로세스를 만들며 죽습니다**.

**⚠️ Gotcha · 순환 임포트**

`a.py`가 `b`를, `b.py`가 `a`를 임포트하면 `ImportError: cannot import name ...`이 납니다. 모듈이 **아직 실행 중**이라 이름이 정의되기 전이기 때문입니다. 해법 순서:

1. 설계를 고칩니다 — 대개 공통 부분을 제3의 모듈로 뽑아야 한다는 신호입니다.
2. `from a import X` 대신 `import a` 후 `a.X`로 **사용 시점**에 접근합니다.
3. 타입 힌트 때문이라면 `if TYPE_CHECKING:` 블록 + 문자열 힌트를 씁니다.
4. 최후 수단으로 함수 안에서 지역 임포트합니다.

**🖥 REPL 퀴즈 — 14-1 · 모듈은 싱글턴**

```python
>>> # config.py 안에 CACHE = {} 가 있다고 하자
>>> import config
>>> config.CACHE["a"] = 1
>>> import config as c2
>>> c2.CACHE
```

---

**🟢 출력 보기**

```text
{'a': 1}
```

모듈은 `sys.modules`에 캐시되므로 몇 번을 임포트해도 **같은 객체 하나**입니다. 파이썬에서 싱글턴을 만드는 가장 자연스러운 방법이 바로 "모듈 수준 변수"인 이유입니다. 반대로 `from config import CACHE`로 값을 직접 가져오면 재대입이 반영되지 않는 함정이 생깁니다.

**🟢 4번 해설**

`from m import C`는 임포트 시점의 **C가 가리키던 객체**를 내 네임스페이스에 새 이름으로 묶습니다. 이후 `m.C = 다른값`은 `m`의 네임스페이스만 바꿉니다. 내 이름은 여전히 옛 객체를 봅니다. 설정값처럼 런타임에 바뀔 수 있는 것은 `import m` 후 `m.C`로 **매번 조회**하거나, 함수로 감싸 반환하세요.
