# 08 · 이터레이션 프로토콜과 제너레이터

`iter · yield · lazy · itertools`

`for`문은 마법이 아니라 **두 개의 메서드를 호출하는 규약**입니다. 이 규약을 이해하면 파일, 소켓, DB 커서, 무한 수열을 전부 같은 문법으로 다룰 수 있습니다.

*for문의 정체*

```python
# 이 코드는
for x in obj:
    body(x)

# 대략 이렇게 동작한다
it = iter(obj)              # obj.__iter__() 호출
while True:
    try:
        x = next(it)        # it.__next__() 호출
    except StopIteration:
        break
    body(x)
```

| 용어 | 조건 | 예 |
| --- | --- | --- |
| iterable(순회 가능) | `__iter__`가 있다 | list, dict, str, 파일 |
| iterator(반복자) | `__next__`와 `__iter__`가 있다 | 제너레이터, `iter(list)`의 결과 |

**⚠️ Gotcha**

반복자는 **한 번 쓰면 소진됩니다**. `g = (x for x in xs)` 이후 `list(g)`를 두 번 하면 두 번째는 빈 리스트입니다. `zip`, `map`, `filter`, `enumerate`, `reversed`, 파일 객체 전부 마찬가지입니다. 두 번 순회해야 하면 리스트로 실체화하세요.

## 제너레이터

*yield*

```python
def read_records(path):
    with open(path, encoding="utf-8") as f:
        for line in f:                  # 파일도 한 줄씩 지연 순회
            line = line.strip()
            if line:
                yield parse(line)       # 여기서 함수가 '멈춘다'

# 1GB 파일도 메모리 몇 KB로 처리
for record in read_records("big.log"):
    handle(record)
```

`yield`가 하나라도 있으면 그 함수는 호출해도 **몸통이 실행되지 않고** 제너레이터 객체만 반환합니다. 첫 `next()`에서 비로소 첫 `yield`까지 실행되고, 지역 변수와 실행 위치를 그대로 보존한 채 멈춥니다.

*파이프라인*

```python
lines   = (l.rstrip("\n") for l in open("access.log", encoding="utf-8"))
records = (parse(l) for l in lines if l)
errors  = (r for r in records if r.status >= 500)

for e in errors:       # 여기 도달하기 전까지 파일은 한 줄도 읽히지 않는다
    alert(e)
```

*yield from · 양방향 통신*

```python
def chain_all(*iterables):
    for it in iterables:
        yield from it          # 위임: 하위 제너레이터에 제어권을 넘긴다

def averager():
    total, count = 0, 0
    while True:
        value = yield (total / count if count else None)   # send()로 값을 받는다
        total += value
        count += 1

avg = averager()
next(avg)          # 첫 yield까지 진행 (priming)
avg.send(10)       # 10.0
avg.send(20)       # 15.0
avg.close()
```

## itertools — 지연 평가 도구상자

*itertools*

```python
from itertools import (islice, chain, groupby, product, combinations,
                       permutations, accumulate, count, cycle, repeat,
                       takewhile, dropwhile, zip_longest, tee, batched)

islice(gen, 10)                     # 무한 수열에서 앞 10개
chain(a, b, c)                      # 이어 붙이기
batched("ABCDEFG", 3)               # 3.12+: ('A','B','C'), ('D','E','F'), ('G',)
accumulate([1, 2, 3, 4])            # 1, 3, 6, 10 (누적합)
takewhile(lambda x: x < 10, nums)   # 조건이 깨지는 순간 중단
zip_longest(a, b, fillvalue=None)   # 길이가 다를 때

# groupby는 정렬된 입력을 전제로 한다 — 연속 구간만 묶는다
for team, members in groupby(sorted(users, key=key), key=key):
    print(team, list(members))
```

**🖥 REPL 퀴즈 — 08-1 · zip과 소진**

```python
>>> xs = [1, 2, 3]
>>> it = iter(xs)
>>> list(zip(it, it))
>>> nums = iter(range(6))
>>> list(zip(*[nums] * 3))
```

---

**🟢 출력 보기**

```text
[(1, 2)]
[(0, 1, 2), (3, 4, 5)]
```

같은 반복자를 여러 번 넘기면 `zip`이 번갈아 `next()`를 호출하며 하나의 스트림을 나눠 씁니다. 첫 줄은 3이 짝을 못 찾아 버려지고, 둘째 줄은 이 성질을 이용한 고전적인 **n개씩 묶기** 관용구입니다(3.12부터는 `batched`가 더 명확합니다).

**🟢 1·3번**

```python
from collections import deque
from itertools import islice

def window(iterable, n):
    it = iter(iterable)
    buf = deque(islice(it, n), maxlen=n)
    if len(buf) == n:
        yield tuple(buf)
    for item in it:
        buf.append(item)          # maxlen 덕분에 왼쪽이 자동으로 밀려난다
        yield tuple(buf)

def batches(iterable, size):
    it = iter(iterable)
    while chunk := list(islice(it, size)):
        yield chunk
```

`tuple(buf)`로 복사해 내보내는 게 중요합니다. `buf` 자체를 yield하면 소비자가 보는 값이 다음 루프에서 바뀌어 버립니다.
