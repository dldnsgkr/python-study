# 파이썬 완전 습득 워크북 — 실습 환경

원본 워크북(`docs/`)의 문제들을 **직접 풀고 즉시 채점받는** 환경입니다.
문제는 723개, 전부 실제로 풀리는지 검증돼 있습니다.

## 처음 한 번만

```bash
./study setup            # 기초·코어·확장 트랙
./study setup backend    # 백엔드 트랙까지 하려면
```

> `uv sync` 를 직접 돌려도 되지만, 그러면 **백엔드 트랙 라이브러리가 제거됩니다**
> (uv 는 환경을 pyproject 와 정확히 일치시킵니다). `./study backend` 가 알아서
> 다시 설치하니 신경 쓰지 않아도 됩니다.

## 매번 쓰는 것

```bash
./study basics     # 기초 트랙 채점 — 지금 어디쯤인지 보여준다
./study next       # 첫 실패 문제 하나만, 실패 이유를 자세히
./study            # 전체 (기초 + 코어 + 확장 + 백엔드)
./study quiz       # 예측 퀴즈 — 실행 전에 출력 맞히기
```

한 파일만 채점하려면:

```bash
./study file b01                       # 파트 번호만
./study file src/basics/b01_variables.py   # 편집 중인 파일 경로 그대로
./study k rotate                       # 이름에 'rotate' 가 든 문제만
```

> 처음엔 아직 아무것도 구현하지 않았으니 거의 다 실패합니다. 정상입니다.
> 실패 목록을 다 읽을 필요 없습니다 — 진행률과 **다음 문제** 한 줄만 보세요.
> `ERROR` 로 나오는 것도 고장이 아니라 "아직 구현 안 된 함수를 불렀다"는 뜻입니다.


캡스톤은 따로 채점합니다: `./study capstone`.
`./study help` 로 나머지 명령을 봅니다.

## 예측 퀴즈 — 읽고 맞히는 연습

```bash
./study quiz            # 아직 못 맞힌 문제부터
./study quiz 04         # 파트별  (04, 시퀀스, 예외 ... 부분 일치)
./study quiz review     # 전에 틀린 것만 다시
```

나머지 문제가 **"함수를 채우고 돌려서 확인"** 이라면, 퀴즈는 **"실행하기 전에 읽고 맞히기"** 입니다.

```
 3/37   04 시퀀스   docs/13_core_04.md

   matrix = [[0] * 2] * 3
   matrix[0][0] = 9
   print(matrix)

 출력은?  (엔터=모르겠음, q=그만)
 > 
```

돌려 보면 알 수 있는 걸 왜 맞히나 싶겠지만, **AI가 짜 준 코드를 검토하려면 이 능력이
필요합니다.** 코드를 읽고 "여기서 이게 나오겠군"이 안 되면, 그럴듯해 보이는 잘못된 코드를
걸러 낼 수 없습니다. 37문제 전부 실제 실행 결과와 대조해 검증돼 있습니다.

틀린 문제는 자동으로 모아 두었다가 `review` 로 다시 물어봅니다.

## 어떻게 공부하나

1. **문서를 읽는다** — `./study doc basics_B1` (또는 `docs/` 를 에디터로 열기)
2. **`src/` 의 함수를 채운다** — 파일 안 docstring이 문제 설명입니다
3. **채점한다** — `./study` 또는 `./study next`
4. 초록불이 되면 다음으로. 막히면 `./study solution b01_variables`

> `src/` 만 고치면 됩니다. `tests/` 는 채점표라 건드리지 마세요.
> 답이 궁금해도 **먼저 30분은 혼자 붙들어 보세요.** 그 30분이 실력이 됩니다.

## 폴더

```
python-study/
├─ docs/          워크북 원문 43개 — 읽기 자료
├─ src/           ← 당신이 채우는 곳
│  ├─ basics/     B1~B15  파이썬 기초 (개념·도구·심화)
│  ├─ kit/        코어 01~19  언어 자체
│  ├─ extra/      확장 드릴  원본 채점 키트에 없던 문제들
│  └─ backend/    B1~B4  pydantic · FastAPI · SQLAlchemy · 운영
├─ tests/         채점표 (읽어 보세요 — 테스트도 학습 자료입니다)
├─ solutions/     모범답안 (다 푼 뒤에)
├─ capstone/      캡스톤 A 로그 분석 CLI + B·C 안내
├─ playground/    자유 실험장 — 여기선 뭘 해도 됩니다
└─ study          학습 도우미 스크립트
```

### 기초 트랙(1번)의 구성

**개념편 B1~B7** — 파이썬이라는 언어가 어떻게 생겼는지

| | |
| --- | --- |
| B1 변수 | 이름과 값 |
| B2 타입 | 정수·실수·문자열·f-문자열 |
| B3 컬렉션 | 리스트·튜플·딕셔너리·세트 |
| B4 흐름 제어 | `if` / `for` |
| B5 함수 | 정의·인자·기본값·`return` |
| B6 클래스 | `__init__`·메서드·인스턴스 |
| B7 `==` 와 `is` | 같은 값 vs 같은 객체, 별칭 |

**도구편 B8~B12** — 실제로 뭔가 만들 때 매일 쓰는 것들

| | |
| --- | --- |
| B8 문자열 다루기 | `split` `join` `strip` `replace` · 인덱싱 · 슬라이싱 `[::-1]` |
| B9 도구상자 | `enumerate` `zip` `.items()` `sorted(key=)` `set` |
| B10 반복의 도구 | `while` `break` `continue` · `range(a,b,step)` · 컴프리헨션 |
| B11 None 과 예외 | `is None` · `try/except/else/finally` · 직접 `raise` |
| B12 파일과 모듈 | `with open(...)` · 읽기/쓰기/덧붙이기 · `if __name__ == "__main__"` |

**심화편 B13~B15** — 함수와 클래스를 끝까지, 그리고 타입 힌트

| | |
| --- | --- |
| B13 함수 더 깊이 | 키워드 전용 인자 · `*args`/`**kwargs` · 여러 값 반환 · `lambda` · 클로저 · `global`/`nonlocal` · 재귀 · 가변 기본값 함정 |
| B14 클래스 더 깊이 | 상속 · `super()` · 오버라이드 · `__str__`/`__repr__`/`__eq__` · 클래스 변수 · `@property` · `@classmethod`/`@staticmethod` · `isinstance` |
| B15 타입 힌트 | 힌트 읽고 **직접 쓰기** · `list[int]` `dict[str,int]` `tuple[str,int]` `int \| None` · 타입 변환 · 런타임엔 아무 일도 안 한다는 것 |

다른 언어를 해 봤다면 개념편은 빠르게 지나갑니다. **도구편과 심화편이 실제 내용입니다** —
`for` 를 알아도 컴프리헨션을 모르면 파이썬 코드를 읽을 수 없고,
타입 힌트를 모르면 이 워크북의 코어·백엔드 트랙을 아예 읽을 수 없습니다.

FastAPI·SQLAlchemy 를 이미 쓰고 있다면 4번(`./study backend`)으로 건너뛸 수도 있습니다.

## 채점 그다음 — 통과가 끝이 아닙니다

원본 워크북의 자가 채점 루브릭입니다. 테스트 통과는 1단계일 뿐입니다.

| 단계 | 기준 | 확인 방법 |
| --- | --- | --- |
| 1 통과 | 테스트가 전부 초록불 | `./study` |
| 2 설명 | 왜 그렇게 구현해야 하는지 한 문장으로 말할 수 있다 | 스스로 |
| 3 타입 | 타입 검사를 통과한다 | `./study types` |
| 4 스타일 | 린트를 통과한다 | `./study lint` |
| 5 확장 | 테스트를 직접 추가해 자기 구현의 빈틈을 찾았다 | 스스로 |

## 백엔드 트랙 (B1~B4) — 채점됩니다

```bash
./study backend    # 라이브러리가 없으면 알아서 설치합니다
```

DB 서버를 띄울 필요가 없습니다. SQLAlchemy 실습은 인메모리 SQLite(aiosqlite)로
**진짜 쿼리를 날려** 채점하고, FastAPI 실습은 httpx 의 ASGI 전송으로 앱을 직접 호출합니다.

| | 무엇을 |
| --- | --- |
| B1 pydantic | 검증 모델 · `ValidationError` 요약 · `BaseSettings` fail fast · 경계/도메인 분리 |
| B2 FastAPI | CRUD 5개 · 도메인 예외 → HTTP 매핑 · 커서 페이지네이션 · `async def` 블로킹 함정 |
| B3 SQLAlchemy | 2.0 선언 모델 · `lazy="raise"` 와 N+1 (쿼리 수를 셉니다) · `with_for_update()` · Protocol 리포지터리 |
| B4 운영 | JSON 로깅 · `contextvars` trace_id · 요청 타이밍 미들웨어 · graceful shutdown |

## 브랜치 — 문제와 내 풀이를 나눠 둡니다

| 브랜치 | 내용 |
| --- | --- |
| `main` | **초기 상태.** 문제(스켈레톤)만 있고 아무것도 구현돼 있지 않습니다 |
| `my-answers` | 내 풀이. 여기서 작업하고 커밋합니다 |

```bash
git switch my-answers      # 여기서 문제를 풉니다
./study file b01
git add -A && git commit -m "B1 변수 풀이"
```

`main` 은 건드리지 마세요. 남이(또는 나중의 내가) 처음부터 다시 풀 수 있는 상태로 남겨 둡니다.

**문제가 추가·수정되면** `main` 을 내 브랜치로 끌어옵니다:

```bash
git switch my-answers
git merge main
```

내가 이미 고친 파일에서 충돌이 날 수 있습니다. 그럴 땐 **내 풀이 쪽을 남기고**
새로 생긴 문제만 받아들이면 됩니다.
