## match: 구조 분해 패턴 매칭

*match (3.10+)*

```python
def handle(event: dict):
    match event:
        case {"type": "click", "pos": (x, y)}:
            return f"click at {x},{y}"
        case {"type": "key", "code": str(code)} if code.isalpha():
            return f"key {code}"
        case {"type": "batch", "items": [first, *rest]}:
            return f"batch head={first} rest={len(rest)}"
        case Point(x=0, y=0):
            return "origin"
        case _:
            return "unknown"
```

**⚠️ Gotcha**

`case Status.OK:`처럼 **점이 있는 이름**은 값 비교지만, `case ok:`처럼 **맨 이름**은 값 비교가 아니라 **캡처 패턴**입니다. 무엇이든 매칭시키고 `ok`라는 변수에 담아 버립니다. 상수와 비교하려면 반드시 `SomeEnum.MEMBER` 형태로 쓰세요.

**☕ JVM 개발자 노트**

Kotlin `when`과 비슷해 보이지만 성격이 다릅니다. `when`은 표현식이고 `match`는 **문**이라 값을 만들지 않습니다. 대신 `match`는 딕셔너리·시퀀스·객체 속성까지 구조 분해합니다. 값을 만들려면 함수로 감싸 `return`하는 위 패턴이 관용적입니다. 3항 연산은 `a if cond else b`입니다.

## 컴프리헨션

*comprehension*

```python
[f(x) for x in xs if cond(x)]              # list
{f(x) for x in xs}                          # set
{k: v for k, v in pairs}                    # dict
(f(x) for x in xs)                          # generator — 지연 평가

# 중첩: for가 나오는 순서는 중첩 for문과 같다
[(i, j) for i in range(3) for j in range(i)]

# 중첩 리스트를 만들 때는 안쪽 컴프리헨션을 값으로
[[0] * cols for _ in range(rows)]
```

기준: **세 줄을 넘거나 조건이 두 개 이상이면 for 루프로 푸세요.** 컴프리헨션은 짧아서 좋은 게 아니라 "무엇을 만드는지"가 한눈에 보여서 좋은 것입니다.

우연히 맞아 보이지만 **운입니다**. 리스트 순회는 내부 인덱스를 쓰기 때문에 원소를 지우면 그다음 원소를 건너뜁니다. `[1,2,2,3]`으로 시도해 보면 2가 남습니다. 정답은 새 리스트를 만드는 것: `xs = [x for x in xs if x % 2]`.

```python

import hashlib
def sha256_of(path):
    h = hashlib.sha256()
    with open(path, "rb") as f:
        while chunk := f.read(4096):
            h.update(chunk)
    return h.hexdigest()
```

`next(제너레이터, 기본값)`은 for-else보다 짧고, 조건을 만족하는 순간 **즉시 멈춥니다**. 전체 리스트 컴프리헨션을 만들고 `[0]`을 취하는 방식과 결정적으로 다릅니다.
