# 17 · 동시성 — GIL, 스레드, 프로세스, asyncio

`무엇을 언제 쓰는가`

CPython에는 **GIL**(Global Interpreter Lock)이 있습니다. 한 프로세스 안에서 파이썬 바이트코드를 실행하는 스레드는 **언제나 하나뿐**입니다. 그래서 선택 기준이 단순합니다.

| 작업 성격 | 도구 | 이유 |
| --- | --- | --- |
| I/O 대기(HTTP, DB, 파일) | `asyncio` 또는 스레드 | 대기 중에는 GIL이 풀린다 |
| CPU 연산 | `multiprocessing` / `ProcessPoolExecutor` | GIL을 우회하려면 프로세스를 나눠야 한다 |
| 수천 개 동시 연결 | `asyncio` | 스레드보다 훨씬 가볍다 |
| 기존 동기 라이브러리 병렬화 | `ThreadPoolExecutor` | 코드 수정이 거의 없다 |

**☕ JVM 개발자 노트**

JVM 스레드는 진짜 병렬 실행이지만 파이썬 스레드는 I/O 대기에서만 이득이 있습니다. 즉 **Spring의 스레드풀 감각으로 CPU 작업을 스레드에 뿌리면 전혀 빨라지지 않습니다.** (3.13의 free-threaded 빌드가 GIL 제거를 실험 중이지만 아직 기본값은 아닙니다.)

## concurrent.futures — 가장 실용적인 출발점

*futures*

```python
from concurrent.futures import ThreadPoolExecutor, ProcessPoolExecutor, as_completed

with ThreadPoolExecutor(max_workers=8) as pool:
    futures = {pool.submit(fetch, url): url for url in urls}
    for fut in as_completed(futures):
        url = futures[fut]
        try:
            data = fut.result()          # 예외는 여기서 다시 발생한다
        except Exception:
            logging.exception("실패: %s", url)

with ProcessPoolExecutor() as pool:      # CPU 작업
    results = list(pool.map(heavy_calc, items, chunksize=100))
```

## asyncio

*async / await*

```python
import asyncio, httpx

async def fetch(client: httpx.AsyncClient, url: str) -> dict:
    resp = await client.get(url, timeout=10)     # 여기서 다른 코루틴에 양보
    resp.raise_for_status()
    return resp.json()

async def main(urls: list[str]) -> list[dict]:
    async with httpx.AsyncClient() as client:
        async with asyncio.TaskGroup() as tg:        # 3.11+
            tasks = [tg.create_task(fetch(client, u)) for u in urls]
    return [t.result() for t in tasks]

asyncio.run(main(urls))
```

*자주 쓰는 패턴*

```python
await asyncio.gather(*coros, return_exceptions=True)   # 예외를 결과로 수집
await asyncio.wait_for(coro, timeout=5)                # 타임아웃
async with asyncio.timeout(5): ...                     # 3.11+ 블록 단위 타임아웃

sem = asyncio.Semaphore(10)                            # 동시 실행 수 제한
async with sem:
    await fetch(...)

await asyncio.to_thread(blocking_func, arg)            # 동기 함수를 스레드로 밀어내기
```

**⚠️ Gotcha**

이벤트 루프 안에서 **동기 블로킹 호출**(`time.sleep`, `requests.get`, 무거운 계산)을 하면 루프 전체가 멈춥니다. 코루틴 하나가 3초 자면 나머지 1000개도 3초 멈춥니다. `await asyncio.sleep()`을 쓰고, 불가피한 동기 코드는 `asyncio.to_thread`로 내보내세요.

**🖥 REPL 퀴즈 — 17-1 · 코루틴은 호출만으로 실행되지 않는다**

```python
>>> async def hello():
...     print("실행됨")
...     return 1
>>> c = hello()
>>> type(c)
>>> asyncio.run(c)
```

---

**🟢 출력 보기**

```text
<class 'coroutine'>
실행됨
1
```

호출은 **코루틴 객체를 만들 뿐**이고 몸통은 실행되지 않습니다(제너레이터와 같은 원리). await 하거나 루프에 넘겨야 실행됩니다. await을 빠뜨리면 "coroutine was never awaited" 경고만 뜨고 로직이 통째로 실행되지 않는, 조용하고 위험한 버그가 됩니다.

**🟢 3번 예시 답**

```python
async def fetch_with_retry(client, url, sem, tries=3):
    async with sem:
        for attempt in range(1, tries + 1):
            try:
                r = await client.get(url, timeout=10)
                r.raise_for_status()
                return r.json()
            except (httpx.HTTPError, httpx.TimeoutException):
                if attempt == tries:
                    raise
                await asyncio.sleep(0.5 * 2 ** (attempt - 1))
```

4번 정리: `TaskGroup`은 **하나가 실패하면 형제 태스크를 모두 취소**하고 `ExceptionGroup`을 던집니다(구조적 동시성). `gather(return_exceptions=True)`는 전부 끝까지 기다리고 예외를 결과 리스트에 담습니다. "일부 실패해도 나머지는 필요"할 때만 후자를 쓰세요.
