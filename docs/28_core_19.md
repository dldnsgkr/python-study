## 비용이 큰 순서대로 고치기

1. **알고리즘** — 리스트 `in`(O(n))을 set(O(1))으로 바꾸는 것이 다른 모든 미시 최적화를 합친 것보다 큽니다.
2. **I/O 횟수** — N+1 쿼리, 반복 HTTP 호출. 배치·캐시로 줄입니다.
3. **파이썬 루프를 라이브러리로** — `sum`, `join`, `numpy`, `pandas`는 C 루프입니다.
4. **불필요한 객체 생성** — 문자열 `+=` 반복, 매 루프의 리스트 재생성.
5. 그다음에야 `__slots__`, 지역 변수 캐싱 같은 미시 최적화.

*자주 만나는 개선*

```python
# 느림 — 매번 전체 스캔
if user_id in allowed_list:          # list, O(n)
allowed = set(allowed_list)          # 한 번 만들고
if user_id in allowed:               # O(1)

# 느림 — 새 문자열을 매번 생성
s = ""
for part in parts: s += part
s = "".join(parts)                   # 빠름

# 느림 — 속성 조회를 루프마다
for x in xs: result.append(transform(x))
append = result.append                # 지역 이름으로 캐시
for x in xs: append(transform(x))
```

## 메모리 모델

CPython은 **참조 카운팅**이 기본이고, 순환 참조를 정리하기 위한 **세대별 GC**가 보조합니다. 참조가 0이 되는 즉시 해제되므로 `with` 없이도 파일이 닫히는 것처럼 보이지만, 이는 구현 세부사항입니다(PyPy는 다릅니다). **리소스는 항상 `with`로 관리하세요.**

*누수의 흔한 원인*

```python
import gc, weakref, sys

sys.getrefcount(obj)        # 참조 수(인자 전달분 +1)
gc.collect()                # 순환 참조 수거

# 1) 전역 캐시가 계속 자란다  → lru_cache(maxsize=...) 또는 TTL 캐시
# 2) 메서드에 @cache → self가 캐시에 갇힌다
# 3) 부모 ↔ 자식 상호 참조 → 한쪽을 weakref.ref 로
# 4) 로깅 핸들러/스레드/구독자 등록 후 해제 누락
```

**🖥 REPL 퀴즈 — 19-1 · 어느 쪽이 빠를까**

```python
>>> import timeit
>>> timeit.timeit("[i*2 for i in range(1000)]", number=10000)
>>> timeit.timeit("list(map(lambda i: i*2, range(1000)))", number=10000)
>>> timeit.timeit("out=[]\nfor i in range(1000): out.append(i*2)", number=10000)
```

---

**🟢 경향 보기**

```text
컴프리헨션 < map+lambda < for+append  (왼쪽이 빠름)
```

컴프리헨션은 전용 바이트코드를 쓰고, `map`은 람다 호출 비용이 붙으며, for+append는 매 루프 속성 조회와 메서드 호출이 있습니다. 다만 `map(str, xs)`처럼 **내장 함수를 직접** 넘기면 map이 가장 빠릅니다. 절대 수치는 환경마다 다르니 항상 직접 재세요.
