# 13 · 예외

`계층 · raise from · EAFP · ExceptionGroup`

*전체 문법*

```python
try:
    result = risky()
except (ValueError, KeyError) as exc:      # 여러 개는 튜플로
    log.warning("복구 가능: %s", exc)
    raise ServiceError("주문 처리 실패") from exc     # 원인 체이닝
except Exception:
    raise                                  # 다시 던지기 (트레이스백 보존)
else:
    commit(result)                         # 예외가 없을 때만
finally:
    release()                              # 언제나 실행
```

## 예외 계층 요약

*hierarchy*

```text
BaseException
├── SystemExit / KeyboardInterrupt / GeneratorExit    ← 잡으면 안 되는 것들
└── Exception
    ├── ArithmeticError → ZeroDivisionError
    ├── LookupError → IndexError, KeyError
    ├── OSError → FileNotFoundError, PermissionError, TimeoutError
    ├── ValueError → UnicodeError
    ├── TypeError, AttributeError, NameError
    └── RuntimeError → RecursionError
```

**⚠️ Gotcha**

`except:`(맨몸)나 `except BaseException:`은 `KeyboardInterrupt`까지 잡아 **Ctrl+C로 종료되지 않는 프로그램**을 만듭니다. 최상위 핸들러는 반드시 `except Exception:`으로 쓰세요.

## EAFP: 파이썬의 기본 태도

*Easier to Ask Forgiveness than Permission* — 먼저 시도하고 실패를 처리합니다. 사전 검사(LBYL)는 검사와 사용 사이에 상태가 바뀌는 경쟁 조건을 만들고, 검사 코드가 중복됩니다.

*LBYL vs EAFP*

```python
# LBYL — 검사 후 파일이 지워지면? 경쟁 조건
if os.path.exists(path):
    with open(path) as f: ...

# EAFP — 파이썬다운 방식
try:
    with open(path, encoding="utf-8") as f: ...
except FileNotFoundError:
    use_default()
```

*커스텀 예외 설계*

```python
class AppError(Exception):
    """이 앱의 모든 예외의 루트 — 호출자가 한 줄로 잡을 수 있게."""

class OrderNotFound(AppError):
    def __init__(self, order_id: str):
        super().__init__(f"주문을 찾을 수 없습니다: {order_id}")
        self.order_id = order_id           # 구조화된 정보를 속성으로
```

**💡 Tip**

라이브러리/모듈마다 **루트 예외 하나**를 두고 나머지를 그 아래에 두세요. 호출자가 `except AppError:` 한 줄로 경계를 그을 수 있고, 나중에 예외를 추가해도 호출부가 안 깨집니다.

*ExceptionGroup (3.11+)*

```python
try:
    async with asyncio.TaskGroup() as tg:      # 여러 태스크가 동시에 실패할 수 있다
        tg.create_task(fetch(1))
        tg.create_task(fetch(2))
except* ConnectionError as eg:                 # except* 는 그룹에서 해당 타입만 골라낸다
    for exc in eg.exceptions:
        log.error("연결 실패: %s", exc)
except* ValueError as eg:
    ...
```

**🖥 REPL 퀴즈 — 13-1 · finally와 return**

```python
>>> def f():
...     try:
...         return "try"
...     finally:
...         return "finally"
>>> f()
>>> def g():
...     try:
...         raise ValueError("x")
...     finally:
...         return "swallowed"
>>> g()
```

---

**🟢 출력 보기**

```text
'finally'
'swallowed'
```

`finally`의 `return`은 앞선 반환값을 덮어쓰고 **진행 중인 예외까지 조용히 삼킵니다**. 실무에서 가장 찾기 어려운 버그 중 하나입니다. `finally` 블록에는 정리 코드만 두고 `return`·`break`·`continue`를 절대 쓰지 마세요.

### 🏋 DRILL 13 — 예외

1. 외부 API 호출을 감싸 `httpx` 예외를 전부 도메인 예외로 변환하는 어댑터를 작성하세요. 원인은 `raise ... from exc`로 보존합니다.
2. `raise X from exc`, `raise X`(except 블록 안), `raise X from None` 세 경우의 트레이스백 출력 차이를 직접 확인하고 정리하세요.
3. 재시도 로직에서 마지막 예외만 던지지 말고 모든 시도의 예외를 `ExceptionGroup`으로 모아 던지도록 바꿔 보세요.
4. 제너레이터가 `finally`에서 리소스를 정리할 때, 소비자가 중간에 `break`하면 정리가 언제 일어나는지 확인하세요(`close()`와 GC 타이밍).

---

**🟢 2번 정리**

- `raise X from exc` → "The above exception was the direct cause…" (명시적 원인)
- except 블록 안에서 그냥 `raise X` → "During handling of the above exception, another exception occurred…" (암묵적 연결, `__context__`)
- `raise X from None` → 이전 예외를 숨김. 내부 구현을 감춰 API 경계를 깔끔히 할 때만 쓰고, 디버깅 정보를 잃는다는 점을 감수해야 합니다.
