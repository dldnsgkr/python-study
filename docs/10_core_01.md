# 01 · 객체 모델 — 파이썬의 1층

`identity · type · value · binding`

파이썬에는 원시 타입이 없습니다. `1`도, `None`도, 함수도, 클래스도, 모듈도 전부 **힙에 놓인 객체**입니다. 모든 객체는 세 가지를 가집니다.

| 속성 | 확인 방법 | 변경 가능? |
| --- | --- | --- |
| identity(정체성) | `id(obj)`, `is` | 절대 불가 |
| type | `type(obj)` | 사실상 불가 |
| value | `==` | 가변 객체만 가능 |

## 변수는 상자가 아니라 이름표다

이 그림을 정확히 갖고 있으면 파이썬 함정의 절반이 사라집니다. 대입은 값을 복사하는 게 아니라 **이름을 객체에 묶는 것**입니다.

*이름 바인딩*

```python
a = [1, 2, 3]
b = a            # 같은 리스트 객체에 이름 하나 더 붙임
b.append(4)
print(a)         # [1, 2, 3, 4]  ← a도 바뀐 것처럼 보인다
print(a is b)    # True

b = [9]          # 재대입은 b라는 이름만 다른 객체로 옮긴다
print(a)         # [1, 2, 3, 4]  ← a는 그대로
```

**☕ JVM 개발자 노트**

Java의 참조 변수와 개념은 같지만 **원시 타입 예외가 없다**는 점이 다릅니다. 또 파이썬의 `is`는 Java의 `==`(참조 비교), 파이썬의 `==`는 `equals()`에 대응합니다. Kotlin의 `===` / `==` 구도와 정확히 같습니다.

## 가변 vs 불변

| 불변(immutable) | 가변(mutable) |
| --- | --- |
| `int, float, bool, str, bytes, tuple, frozenset, range, None` | `list, dict, set, bytearray`, 대부분의 사용자 정의 클래스 |

불변은 "값이 안 바뀐다"가 아니라 **바꾸는 연산 자체를 제공하지 않는다**는 뜻입니다. `s += "x"`는 새 문자열을 만들어 다시 바인딩합니다.

**🖥 REPL 퀴즈 — 01-1 · 정수 캐싱**

```python
>>> a = 256
>>> b = 256
>>> a is b
>>> x = 257
>>> y = 257
>>> x is y
>>> x == y
```

CPython은 -5~256 사이 작은 정수를 미리 만들어 재사용합니다. **구현 세부사항이지 언어 명세가 아닙니다.** 결론: 값 비교는 언제나 `==`, `is`는 `None`·싱글턴·동일 객체 판별에만 씁니다.

## 복사: 얕게, 깊게

*copy*

```python
import copy

matrix = [[1, 2], [3, 4]]

shallow = matrix[:]                 # list(matrix), copy.copy(matrix) 와 동일
deep = copy.deepcopy(matrix)

shallow[0].append(99)
print(matrix)   # [[1, 2, 99], [3, 4]]  ← 안쪽 리스트는 공유된다
print(deep)     # [[1, 2], [3, 4]]
```

**⚠️ Gotcha**

얕은 복사는 **바깥 컨테이너만** 새로 만듭니다. 중첩 구조라면 `deepcopy`를 쓰거나, 애초에 불변 자료구조(`tuple`, `frozenset`, `@dataclass(frozen=True)`)로 설계해 복사 문제 자체를 없애는 편이 낫습니다.

## 진리값: 모든 객체는 참/거짓을 가진다

`if x:`는 `bool(x)`를 호출하고, 이는 `__bool__` → 없으면 `__len__` → 둘 다 없으면 True 순으로 결정됩니다.

- 거짓: `False, None, 0, 0.0, 0j, Decimal(0), '', [], (), {}, set(), range(0)`
- 그 외 전부 참

**⚠️ Gotcha**

`if not value:`는 `None`과 `0`, 빈 리스트를 **구분하지 못합니다**. "값이 안 들어왔는지"를 검사하려면 `if value is None:`을 쓰세요. 개수·금액처럼 0이 유효한 값일 때 실제 버그로 이어집니다.

**🟢 1·2번**

1번: `([1, 2, 4], 3)`이 출력되고 마지막 줄은 `TypeError`. 튜플의 불변성은 **튜플이 들고 있는 참조가 고정**이라는 뜻이지, 참조가 가리키는 객체까지 얼린다는 뜻이 아닙니다. 그래서 가변 원소를 담은 튜플은 해시도 불가능합니다.

2번: `str`은 불변이라 아이템 대입 프로토콜(`__setitem__`)을 구현하지 않습니다. "못 바꾸게 막는" 게 아니라 "바꾸는 연산이 아예 정의돼 있지 않은" 것입니다.

**🟢 3번 예시 답**

```python
import copy

def with_key(d: dict, path: list[str], value):
    result = copy.deepcopy(d)
    cursor = result
    for key in path[:-1]:
        cursor = cursor.setdefault(key, {})
    cursor[path[-1]] = value
    return result
```

얕은 복사만 하면 중첩 dict를 공유해 원본이 오염됩니다. 성능이 중요하면 경로 위 노드만 복사하는 path copy로 최적화할 수 있습니다.
