# 09 · 데코레이터

`함수를 감싸는 함수 · wraps · 매개변수화`

데코레이터는 특별한 기능이 아니라 **문법 설탕**입니다. `@deco`는 정확히 `func = deco(func)`입니다.

*기본형*

```python
import functools, time, logging

def timed(func):
    @functools.wraps(func)              # 원본의 __name__, __doc__, 시그니처 보존
    def wrapper(*args, **kwargs):
        start = time.perf_counter()
        try:
            return func(*args, **kwargs)
        finally:
            elapsed = time.perf_counter() - start
            logging.info("%s took %.3fs", func.__name__, elapsed)
    return wrapper

@timed
def sync_orders(shop_id: int) -> int:
    ...
```

**⚠️ Gotcha**

`@functools.wraps`를 빠뜨리면 모든 데코레이트된 함수의 `__name__`이 `wrapper`가 되고 docstring과 타입 힌트가 사라집니다. 로깅·모니터링·문서화·프레임워크 라우팅이 전부 조용히 망가집니다. **예외 없이 붙이세요.**

## 인자를 받는 데코레이터 = 데코레이터를 만드는 함수

*parameterized*

```python
def retry(times=3, delay=0.5, exceptions=(ConnectionError,)):
    def decorator(func):
        @functools.wraps(func)
        def wrapper(*args, **kwargs):
            last = None
            for attempt in range(1, times + 1):
                try:
                    return func(*args, **kwargs)
                except exceptions as exc:
                    last = exc
                    if attempt < times:
                        time.sleep(delay * 2 ** (attempt - 1))   # 지수 백오프
            raise last
        return wrapper
    return decorator

@retry(times=5, delay=0.2)
def call_api(): ...
```

계층이 3단이라 헷갈립니다. 읽는 순서: `retry(times=5)`가 먼저 **실행**되어 `decorator`를 만들고, 그 `decorator`가 `call_api`를 받아 `wrapper`로 바꿉니다.

*클래스 기반 · 클래스 데코레이터*

```python
class CountCalls:
    def __init__(self, func):
        functools.update_wrapper(self, func)
        self.func, self.count = func, 0
    def __call__(self, *args, **kwargs):
        self.count += 1
        return self.func(*args, **kwargs)

def register(cls):                 # 클래스를 받아 클래스를 반환
    HANDLERS[cls.event_type] = cls
    return cls

@register
class ClickHandler:

```

**☕ JVM 개발자 노트**

Java 어노테이션은 **메타데이터**일 뿐이고 실제 동작은 리플렉션이나 프록시가 담당합니다. 파이썬 데코레이터는 **정의 시점에 즉시 실행되어 객체를 바꿔치기**합니다. Spring AOP가 컴파일/런타임 프록시로 하는 일을 언어 문법 한 줄로 하는 셈입니다. 대신 정의 시점 부작용이 있어 임포트만 해도 실행된다는 점을 기억하세요.

**🟢 3번 예시 답**

```python
import functools, inspect, time

def timed(func):
    if inspect.iscoroutinefunction(func):
        @functools.wraps(func)
        async def awrapper(*a, **kw):
            t = time.perf_counter()
            try:
                return await func(*a, **kw)
            finally:
                print(f"{func.__name__}: {time.perf_counter() - t:.3f}s")
        return awrapper

    @functools.wraps(func)
    def wrapper(*a, **kw):
        t = time.perf_counter()
        try:
            return func(*a, **kw)
        finally:
            print(f"{func.__name__}: {time.perf_counter() - t:.3f}s")
    return wrapper
```

비동기 함수에 동기 wrapper를 씌우면 코루틴 객체를 반환할 뿐 실행되지 않아 "await 안 됨" 경고만 뜨고 조용히 실패합니다. 17파트와 함께 보세요.
