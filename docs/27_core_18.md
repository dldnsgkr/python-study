# 18 · 테스트와 품질 도구

`pytest · fixture · mock · ruff · mypy`

*pytest 기본*

```python
# tests/test_order.py
import pytest
from myapp.domain import Order, InsufficientStock

def test_total_includes_vat():
    order = Order(items=[("A", 2, 1000)])
    assert order.total() == 2200          # 평범한 assert 만으로 충분

def test_raises_when_out_of_stock():
    with pytest.raises(InsufficientStock, match="A"):
        Order(items=[("A", 999, 1000)]).place()

@pytest.mark.parametrize(
    "qty,price,expected",
    [(1, 1000, 1100), (2, 1000, 2200), (0, 1000, 0)],
    ids=["single", "double", "zero"],
)
def test_totals(qty, price, expected):
    assert Order(items=[("A", qty, price)]).total() == expected
```

*fixture*

```python
# conftest.py — 같은 디렉터리 이하 모든 테스트가 공유
import pytest

@pytest.fixture
def db():
    conn = create_test_db()
    yield conn                 # yield 앞은 setup, 뒤는 teardown
    conn.rollback(); conn.close()

@pytest.fixture(scope="session")
def app_config():
    return load_config("test")

def test_save(db):             # 인자 이름으로 주입 — DI 컨테이너처럼 동작
    save(db, Order(...))
    assert count(db) == 1
```

*mock*

```python
from unittest.mock import Mock, patch, AsyncMock

def test_notify(monkeypatch):
    sender = Mock(return_value=True)
    monkeypatch.setattr("myapp.notify.send_sms", sender)

    notify_user("010-0000-0000", "안녕")

    sender.assert_called_once_with("010-0000-0000", "안녕")

@patch("myapp.adapters.httpx.AsyncClient.get", new_callable=AsyncMock)
def test_fetch(mock_get): ...
```

**💡 Tip**

패치는 **정의된 곳이 아니라 사용되는 곳**을 대상으로 합니다. `myapp.service`가 `from myapp.mailer import send`로 가져왔다면 `patch("myapp.service.send")`여야 합니다. 이 규칙 하나가 mock 실패의 절반입니다.

*품질 파이프라인*

```python
ruff format .          # 포매팅
ruff check --fix .     # 린트 + 자동 수정
mypy src               # 정적 타입 검사
pytest -q --cov=src --cov-report=term-missing
```

**☕ JVM 개발자 노트**

pytest fixture는 스프링의 DI + `@BeforeEach`를 합친 물건이라고 보면 감이 옵니다. 스코프(`function`/`class`/`module`/`session`)가 빈 스코프에 대응합니다. JUnit의 `assertEquals`류 API가 없어도 되는 이유는 pytest가 `assert` 문을 재작성해 실패 시 좌우 값 차이를 직접 보여 주기 때문입니다.

**🟢 3번 힌트**

```python
# 나쁨: 내부에서 now()를 직접 호출 → 테스트에서 제어 불가
def is_expired(token): return token.exp < datetime.now(UTC)

# 좋음: 시간도 의존성이다
def is_expired(token, now: datetime | None = None) -> bool:
    now = now or datetime.now(UTC)
    return token.exp < now
```

시간·난수·UUID·파일시스템·네트워크는 전부 "제어할 수 없는 의존성"입니다. 경계로 밀어내면 mock 없이도 대부분 테스트할 수 있습니다.
