# 07 · 함수 — 시그니처의 모든 것

`arguments · scope · closure · functools`

## 인자 종류 전부

*signature*

```python
def f(pos_only, /, standard, *args, kw_only, **kwargs):
    ...

# /  앞: 위치로만 전달 가능 (키워드 이름으로 호출 불가)
# /  뒤 ~ * 앞: 위치·키워드 둘 다 가능
# *  뒤: 키워드로만 전달 가능
```

*실전 예*

```python
def create_user(name, email, *, is_admin=False, send_mail=True):
    ...

create_user("kim", "k@x.com", is_admin=True)      # OK
create_user("kim", "k@x.com", True)               # TypeError — 의도된 설계
```

**💡 Tip**

불리언 플래그나 옵션은 `*` 뒤로 밀어 **키워드 전용**으로 만드세요. 호출부에서 `True, False, True` 같은 정체불명 인자 나열을 막고, 나중에 인자 순서를 바꿔도 호출부가 깨지지 않습니다.

## 기본값 함정 — 파이썬 1위 함정

*mutable default*

```python
# 잘못된 코드
def add_item(item, basket=[]):
    basket.append(item)
    return basket

add_item("a")    # ['a']
add_item("b")    # ['a', 'b']   ← ?!

# 올바른 코드
def add_item(item, basket=None):
    if basket is None:
        basket = []
    basket.append(item)
    return basket
```

기본값은 **함수 정의 시점에 딱 한 번** 평가되어 `func.__defaults__`에 저장됩니다. 호출할 때마다 새로 만들어지지 않습니다. 같은 이유로 `def log(ts=datetime.now())`도 임포트 시각에 고정됩니다.

## 스코프: LEGB

이름을 찾는 순서는 **Local → Enclosing → Global → Built-in**. 그리고 파이썬의 핵심 규칙: **함수 안에서 이름에 대입하면 그 이름은 그 함수의 지역 변수가 된다**(대입문이 아래쪽에 있어도 함수 전체에 적용).

*scope*

```python
count = 0

def bump():
    count += 1          # UnboundLocalError!  count가 지역 변수로 승격됨

def bump_ok():
    global count
    count += 1

def outer():
    total = 0
    def inner():
        nonlocal total   # 바깥 함수(Enclosing)의 이름을 수정
        total += 1
    inner()
    return total         # 1
```

**☕ JVM 개발자 노트**

Java 람다는 사실상 final인 지역 변수만 캡처합니다. 파이썬 클로저는 **변수 자체를 참조로 캡처**하므로 값이 나중에 바뀌면 클로저가 보는 값도 바뀝니다. 아래 퀴즈가 정확히 그 차이입니다.

**🖥 REPL 퀴즈 — 07-1 · 늦은 바인딩**

```python
>>> fs = [lambda: i for i in range(3)]
>>> [f() for f in fs]
>>> gs = [lambda i=i: i for i in range(3)]
>>> [g() for g in gs]
```

---

**🟢 출력 보기**

```text
[2, 2, 2]
[0, 1, 2]
```

람다는 `i`의 **값**이 아니라 **이름**을 캡처합니다. 호출 시점에 `i`는 이미 2입니다. 기본값 인자는 정의 시점에 평가되므로(위의 "함정"이 여기선 해법이 됩니다) 값이 고정됩니다. `functools.partial(lambda i: i, i)`도 같은 효과입니다.

## 일급 함수와 functools

*functools*

```python
from functools import partial, reduce, cache, lru_cache, singledispatch, wraps

send_json = partial(send, content_type="application/json")

@cache                       # 무제한 메모이제이션 (3.9+)
def fib(n): return n if n < 2 else fib(n-1) + fib(n-2)

@lru_cache(maxsize=1024)     # 크기 제한
def fetch_config(env: str): ...

@singledispatch               # 첫 인자 타입으로 디스패치 (오버로딩 대용)
def render(value): return str(value)

@render.register
def _(value: list): return ", ".join(map(str, value))
```

**⚠️ Gotcha**

`@cache`는 인자를 키로 잡으므로 인자가 **해시 가능**해야 합니다. 리스트·dict를 받는 함수에는 못 씁니다. 또 메서드에 붙이면 `self`까지 캐시 키에 들어가 **인스턴스가 영원히 해제되지 않는** 메모리 누수를 만듭니다.

**🟢 1·3번**

```python
import inspect

def bind_args(func, *args, **kwargs) -> dict:
    bound = inspect.signature(func).bind(*args, **kwargs)
    bound.apply_defaults()
    return dict(bound.arguments)

def make_counter(start=0):
    count = start
    def counter():
        nonlocal count
        count += 1
        return count
    return counter
```

4번 힌트: 람다는 pickle되지 않아 `multiprocessing`에 넘길 수 없지만 `partial`은 대상 함수가 모듈 최상위면 가능합니다. 병렬 처리 코드에서 실제로 부딪히는 차이입니다.
